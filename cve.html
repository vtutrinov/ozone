    CVE-2019-17531

    Эта уязвимость представляет собой комбинацию двух проблем: небезопасной десериализации в Jackson и известной уязвимости в библиотеке логирования Log4j.

    Наличие в системе библиотеки apache-log4j-extra (версии 1.2.x). Эта библиотека содержит уязвимый класс JndiLookup.
    Внешний JSON-эндпоинт. Приложение должно принимать JSON-данные из внешних источников (например, из интернета).

При его обработке уязвимый Log4j выполнит поиск по JNDI, что позволит атакующему указать адрес своего сервера. Это приведёт к загрузке и выполнению вредоносного кода с сервера злоумышленника на вашем сервере.

    CVE-2025-41249

    Эта проблема возникает, когда приложение использует механизм безопасности Spring Security (в частности, аннотацию @EnableMethodSecurity) для контроля доступа к методам.

    Суть проблемы: механизм обнаружения аннотаций (например, @PreAuthorize, @Secured) не всегда корректно работает, если эти аннотации стоят на методах внутри иерархии классов с общими (generic) типами.
    В чём опасность: если разработчик поставил аннотацию для ограничения доступа на метод в родительском классе, а дочерний класс его унаследовал, Spring может «не увидеть» эту аннотацию. В результате доступ к методу может быть разрешён тем, у кого его быть не должно.
    Кого это касается: только те приложения, которые активно используют @EnableMethodSecurity и сложную архитектуру с дженериками для реализации безопасности.

    Версия:5.3.27

    Вендор:org.springframework
